# v1.2.0-dev.2 — isolamento do refresh de dados temporarios

## Contexto

Durante o teste da branch `feature/v1.2.0-versioned-research-data` foi
identificado que a combinacao:

```python
USAR_DADOS_PESQUISA_CONGELADOS = False
FORCAR_DOWNLOAD = True
```

apontava incorretamente para `dados/pesquisa_v1/` e executava
`clear_generated()` sobre o snapshot oficial da pesquisa.

Esse comportamento contrariava a finalidade do teste: baixar novamente todas as
series temporais e Corporate Actions da Alpaca sem modificar os arquivos
congelados da pesquisa.

## Correcao

A partir da versao `1.2.0-dev.2`:

- `USAR_DADOS_PESQUISA_CONGELADOS=True` usa somente
  `dados/pesquisa_v1/`, sem download e sem alteracao.
- `USAR_DADOS_PESQUISA_CONGELADOS=False` usa sempre
  `dados/temporario/reproducao_v1/`.
- `FORCAR_DOWNLOAD=False` reutiliza os arquivos temporarios existentes e
  baixa somente o que estiver ausente.
- `FORCAR_DOWNLOAD=True` limpa somente a pasta temporaria e baixa novamente
  todos os arquivos da Alpaca.
- A combinacao `USAR_DADOS_PESQUISA_CONGELADOS=True` com
  `FORCAR_DOWNLOAD=True` continua invalida.

## Impacto

O snapshot oficial `dados/pesquisa_v1/` deixa de ser um destino possivel do
fluxo de refresh temporario. Isso reduz o risco de alterar acidentalmente a
evidencia congelada usada na reproducao final do TCC.

A mudanca nao altera a estrategia, os modelos, os folds nem os parametros do
experimento.

## Testes

O teste `test_spyder_data_modes_protect_frozen_research_snapshot` foi
atualizado para exigir:

- uso explicito de `CAMINHOS_TEMPORARIOS` no fluxo de download;
- ausencia do antigo modo `atualizar-pesquisa-versionada`;
- uso de `replace=FORCAR_DOWNLOAD`;
- manutencao do modo `pesquisa-versionada`.
