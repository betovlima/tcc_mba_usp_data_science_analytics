# v1.2.0-dev.6 — correcao de imports apos renomeacao do engine

## Problema

A primeira versao da refatoracao para portugues (`1.2.0-dev.5`) renomeou
corretamente varias funcoes em `engine/rotacao.py`, mas
`engine/modelo_lightgbm.py` ainda importava e chamava sete nomes antigos:

- `_analysis_decision_dates`
- `_model_utilities`
- `_precompute_model_utilities`
- `_scheduled_policy`
- `_simple_policy_growth`
- `_simulate_exact`
- `_utility_policy`

Isso causava `ImportError` ao importar `reproducao.experimento` ou executar
`reproduzir_experimento_spyder.py`.

## Causa

Os testes anteriores validavam estrutura, nomes de arquivos e algumas funcoes,
mas nao importavam o grafo completo de modulos do runtime. Por isso o GitHub
Actions da `dev.5` passou mesmo com uma referencia cruzada antiga.

## Correcao

As sete referencias foram atualizadas para os nomes em portugues:

- `_datas_decisao_analise`
- `_utilidades_modelo`
- `_precalcular_utilidades_modelo`
- `_politica_agendada`
- `_crescimento_politica_simples`
- `_simular_exato`
- `_politica_utilidade`

## Protecao adicionada

Foi criado o teste `test_all_runtime_modules_import_successfully`, que importa:

- `engine.configuracao`
- `engine.diagnosticos`
- `engine.execucao`
- `engine.rotacao`
- `engine.modelo_lightgbm`
- `reproducao.artefatos`
- `reproducao.dados`
- `reproducao.preparacao`
- `reproducao.experimento`

Esse teste passa a detectar imports quebrados durante o CI.

## Branch

`refactor/v1.2.0-engine-portugues`

## Impacto esperado

Nenhuma alteracao cientifica ou numerica. A correcao apenas completa a
renomeacao de referencias internas.

## Proximo passo

Executar Ruff e pytest no CI, atualizar a branch local, reiniciar o kernel do
Spyder para remover modulos antigos em memoria e executar novamente a
reproducao reutilizando os mesmos dados temporarios.
