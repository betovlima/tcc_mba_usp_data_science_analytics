# v1.2.0-dev.5 — engine em portugues

## Objetivo

Renomear os modulos e as funcoes internas do pacote `engine` para portugues
sem alterar a semantica cientifica, os parametros, os schemas de dados ou os
nomes tecnicos externos.

Esta alteracao foi feita em uma branch isolada:

`refactor/v1.2.0-engine-portugues`

A branch de origem `feature/v1.2.0-versioned-research-data` permanece intacta.

## Arquivos renomeados

- `engine/config.py` -> `engine/configuracao.py`
- `engine/diagnostics.py` -> `engine/diagnosticos.py`
- `engine/execution.py` -> `engine/execucao.py`
- `engine/lightgbm.py` -> `engine/modelo_lightgbm.py`
- `engine/rotation.py` -> `engine/rotacao.py`

`engine/__init__.py` nao foi renomeado porque esse nome faz parte do mecanismo
de pacotes do Python.

## Nomes mantidos de proposito

Foram mantidos nomes tecnicos reconheciveis quando a traducao reduziria clareza
ou poderia interferir em contratos existentes. Exemplos: `LightGBM`, `RSI`,
`CAGR`, `Sharpe`, `drawdown`, `walk-forward`, `fold`, `BUY`,
`SELL` e chaves dos artefatos JSON/CSV.

Classes e campos da configuracao tambem nao foram renomeados nesta etapa. Eles
fazem parte de um contrato interno amplo e devem ser tratados separadamente se
houver necessidade.

Funcoes locais genericas usadas apenas como callbacks internos, como
`policy`, `callback` e `report`, foram mantidas nesta primeira migracao
para reduzir o risco mecanico do refactor.

## Protecoes

- imports externos foram atualizados;
- referencias cruzadas entre os modulos do `engine` foram atualizadas;
- os testes apontam apenas para os novos nomes;
- o teste de estrutura exige que os antigos arquivos nao existam;
- a versao cientifica passou para `1.2.0-dev.5`.

## Validacao necessaria

Antes de qualquer merge, a branch deve passar por:

1. Ruff;
2. pytest completo;
3. execucao local no Spyder reutilizando o mesmo snapshot da `dev.4`;
4. comparacao dos resultados numericos com a execucao anterior.

Nenhuma diferenca numerica e esperada, pois esta versao e somente um refactor
de nomes.
